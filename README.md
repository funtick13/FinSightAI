# Моно‑репозиторий FinSight AI

Этот репозиторий содержит исходный код дипломного проекта **FinSight AI**.  Проект
организован как моно‑репозиторий с отдельными каталогами для мобильного
приложения, серверной части, AI‑сервиса, инфраструктурных конфигураций и
документации.  Каждая часть может развиваться и поддерживаться отдельно,
но при этом находится в одном общем репозитории.

## Структура

```
FinSightAI/
├── mobile/        # Flutter‑приложение
├── backend/       # сервер на Spring Boot
├── ai-service/    # Python‑сервис искусственного интеллекта (FastAPI)
├── docs/          # документация (архитектура, API и т.п.)
├── infra/         # Docker и конфигурация деплоя
└── storage/       # хранилище PDF‑выписок на сервере
```

### `mobile/`

Содержит код Flutter‑приложения.  На этом этапе здесь находятся минимальные
файлы `main.dart` и `pubspec.yaml`, которые можно расширять по мере развития
проекта.

### `backend/`

Содержит заготовку проекта Spring Boot.  Включает минимальный класс
`Application.java` и файл Maven `pom.xml`.  Дополнительные пакеты и
конфигурации следует добавлять по мере развития серверной части.

### `ai-service/`

Содержит Python‑сервис, реализованный на FastAPI.  В минимальной
реализации доступны два эндпоинта:

* `GET /health` — проверка работоспособности сервиса;
* `POST /analyze` — заглушка, принимающая данные выписки и
  возвращающая фиктивный результат анализа.  В дальнейшем здесь будет
  реализована правило‑ориентированная логика рекомендаций, описанная в
  техническом задании.

### `docs/`

Содержит Markdown‑файлы, описывающие архитектуру на высоком уровне,
структуру API, схему базы данных и объём MVP.  Эти файлы являются
«живой» документацией и должны обновляться по мере развития проекта.

### `infra/`

Содержит инфраструктурные файлы и артефакты деплоя.  Стартовый файл
`docker-compose.yml` помогает координировать работу базы данных, backend
и AI‑сервиса.  При необходимости корректируйте определения сервисов и
переменные окружения.

### `storage/`

Каталог, предназначенный для хранения загруженных PDF‑выписок на
сервере.  В репозиторий включён пустой файл `.gitkeep`, чтобы этот
каталог отслеживался системой контроля версий.

---

Эта заготовка намеренно минимальна.  Она служит основой для
построения функциональности, описанной в техническом задании.  На
следующих этапах будут добавлены аутентификация, загрузка PDF,
парсинг, аналитика, асинхронная обработка, пользовательский интерфейс и
рекомендации.
