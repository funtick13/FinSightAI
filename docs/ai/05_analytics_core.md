# 05. Ядро аналитики (`AnalyticsProvider`)

## Цель

`AnalyticsProvider` — основное аналитическое ядро AI‑сервиса. Оно получает список транзакций и вычисляет базовые финансовые показатели: доходы, расходы, баланс, статистику по категориям и список топ‑категорий. Эти данные нужны для последующих шагов анализа — определения финансового состояния, поиска паттернов, генерации инсайтов и рекомендаций.

## Входные данные

`AnalyticsProvider` принимает объект `AnalysisRequest` с полем `transactions`, где каждая транзакция имеет следующие свойства:

- `id`: идентификатор операции;
- `date`: дата операции;
- `amount`: сумма (положительное число — доход, отрицательное — расход);
- `category`: категория расходов или доходов;
- `currency` и `description` (опционально).

## Выходные данные

Результатом работы является объект с полями:

- `totalIncome`: суммарная сумма всех положительных `amount` (доходов);
- `totalExpense`: суммарная сумма абсолютных значений всех отрицательных `amount` (расходов);
- `balance`: `totalIncome – totalExpense`;
- `categories`: список записей `{ category, amount, percent, operationsCount }`, отсортированных по убыванию суммы;
- `topCategories`: первые три элемента из `categories` (если категорий меньше трёх — все);
- `currency`: валюта, в которой ведётся анализ.

## Алгоритм расчётов

1. **Фильтрация транзакций.** Удаляем операции с нулевой суммой или отсутствующей категорией (при необходимости). Если список операций пуст, возвращаем статус `NO_DATA`【turn2file0†L31-L41】.
2. **Разделение доходов и расходов.** Для каждой транзакции:
   - если `amount > 0` — добавляем к `totalIncome`;
   - если `amount < 0` — прибавляем `abs(amount)` к `totalExpense`.
3. **Расчёт баланса.** `balance = totalIncome – totalExpense`. Если `totalIncome` и `totalExpense` равны 0, баланс 0.
4. **Группировка по категориям.** Проходим по расходам (`amount < 0`), суммируем абсолютные значения по полю `category`, считаем `operationsCount` и долю `percent = amount / totalExpense * 100`. Доли округляются до одного – двух знаков после запятой (например, 37,4 %).
5. **Сортировка категорий.** Список категорий сортируем по убыванию суммы. Если доли равны — по алфавиту категории.
6. **Выбор топ‑3.** Берём первые три элемента (могут быть меньше трёх, если категорий мало). Эти данные используются для инсайтов и рекомендаций【turn2file0†L22-L31】.

## Правила обработки

- **Разные валюты.** Если транзакции в разных валютах, следует конвертировать их в базовую валюту (например, рубли или евро) по курсу на дату операции. Конвертацию можно реализовать в отдельном сервисе или на стороне backend‑а.
- **Пустой список.** При отсутствии расходов или доходов возвращается `NO_DATA` и пустые поля; модуль `StatePredictor` вернёт состояние `NO_DATA`.
- **Округление.** Процентные доли категорий рекомендуется округлять до одного знака после запятой. Суммарная сумма долей должна быть равна 100 % (с учётом округления).
- **Валидность данных.** Если сумма не является числом или категория пустая, следует вернуть `INVALID_INPUT`.

## Пример

Входной список транзакций:

| id | date | amount | category |
|----|------|--------|----------|
| 1  | 2026‑03‑05 | 1000 | Зарплата |
| 2  | 2026‑03‑07 | −200 | Продукты |
| 3  | 2026‑03‑08 | −150 | Транспорт |
| 4  | 2026‑03‑10 | −650 | Развлечения |

Результат `AnalyticsProvider`:

- `totalIncome = 1 000`, `totalExpense = 1 000`, `balance = 0`;
- `categories`: Продукты (200; 20 %; 1 операция), Транспорт (150; 15 %; 1), Развлечения (650; 65 %; 1);
- `topCategories`: Развлечения, Продукты, Транспорт.

Эти данные затем передаются в `StatePredictor`, `PatternDetector`, `InsightGenerator` и `RecommendationGenerator`.
