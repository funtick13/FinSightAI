# 06. Определение финансового состояния (`StatePredictor`)

## Цель

Компонент `StatePredictor` присваивает пользователю одно из нескольких финансовых состояний на основе суммарных показателей из `AnalyticsProvider`. В MVP используется **rule‑based** подход: состояние определяется на основе простых правил и пороговых значений. Поддержка моделей машинного обучения (например, CatBoost) предусмотрена на следующих этапах развития【turn2file1†L5-L10】.

## Возможные состояния

| Состояние | Описание |
|-----------|---------|
| **`STABLE`** | Доходы превышают или примерно равны расходам, доля крупнейшей категории не превышает порога, баланс положителен или около нуля. |
| **`RISKY`** | Расходы значительно превышают доходы; баланс отрицательный, есть риск ухода в минус. |
| **`EXPENSE_HEAVY`** | Высокая концентрация расходов: одна из категорий занимает значительную долю общего расхода (например, ≥ 35 %), хотя суммарные доходы могут покрывать расходы. |
| **`LOW_SAVINGS`** | Доходы превышают расходы, но расходы растут, баланс невелик, и доля расходов по «необязательным» категориям превышает порог. |
| **`NO_DATA`** | Недостаточно данных для анализа (пустой список операций). |

Список состояний может быть расширен по мере развития системы. Названия и границы состояний должны быть понятны конечному пользователю.

## Правила классификации

Псевдокод rule‑based предиктора:

```pseudo
if no transactions:
    return NO_DATA

// Пороговые значения (могут быть вынесены в конфигурацию)
INCOME_EXPENSE_RATIO_STABLE = 0.9  // доходы >= 90 % расходов
TOP_CATEGORY_THRESHOLD = 0.35      // 35 %
BALANCE_THRESHOLD = 0.1            // 10 % от доходов

// Вычисляем отношение доходов к расходам и долю крупнейшей категории
ratio = totalIncome / totalExpense  // если totalExpense = 0, считаем ratio = +∞
maxCategoryPercent = max(categoryAnalytics.percent)

if ratio < 0.8:
    return RISKY

if maxCategoryPercent >= TOP_CATEGORY_THRESHOLD:
    return EXPENSE_HEAVY

if ratio >= 1 and balance / totalIncome < BALANCE_THRESHOLD:
    return LOW_SAVINGS

return STABLE
```

**Объяснения правил:**

1. **`RISKY`** — если расходы значительно превышают доходы (отношение < 0.8), баланс заведомо отрицательный: пользователю рекомендуется пересмотреть бюджет.
2. **`EXPENSE_HEAVY`** — если одна категория занимает ≥ 35 % расходов, даже при положительном балансе, это говорит о высокой концентрации. Следует обратить внимание на эту категорию.
3. **`LOW_SAVINGS`** — если доходы превышают расходы, но баланс составляет < 10 % от доходов (низкая способность к накоплению), сервис рекомендует увеличить сбережения.
4. **`STABLE`** — в остальных случаях: доходы приблизительно равны расходам, доли распределены равномерно.
5. **`NO_DATA`** — когда отсутствуют транзакции; анализ невозможен【turn2file0†L31-L41】.

Пороговые значения можно настраивать и адаптировать под разные профили пользователей. Правила следует задокументировать, чтобы они были понятны, и сопровождать примерами.

## Пример

Пусть `totalIncome = 50 000`, `totalExpense = 60 000`, `balance = −10 000`, максимальная доля категории = 40 %. Отношение доходов к расходам = 0.83. Согласно правилам:

- отношение < 0.8 → нет;
- maxCategoryPercent ≥ 35 % → да; следовательно, состояние = `EXPENSE_HEAVY` (категория с 40 % расходов).

Если те же показатели, но maxCategoryPercent = 25 % и отношение доходов к расходам = 0.83, то возвращается `RISKY` (расходы > доходы). Если доходы = 60 000, расходы = 50 000, баланс = 10 000 (16 % от доходов), maxCategoryPercent = 20 %, то состояние = `STABLE`.

## Возможные расширения

В перспективе предиктор может быть заменён или дополнен ML‑моделью. Для этого требуется сбор исторических данных пользователей и разработка `CatBoostStatePredictor`. Модель может учитывать дополнительные признаки (частота трат, тренды по времени, соотношение обязательных и необязательных расходов) и выдавать более точный прогноз состояния. Об этом подробно сказано в документе `14_ml_extension_plan.md`【turn2file1†L5-L10】.
