# 07. Обнаружение паттернов расходов (`PatternDetector`)

## Цель

`PatternDetector` анализирует агрегированные данные из `AnalyticsProvider` и выявляет значимые паттерны в расходах пользователя. Паттерны помогают понять привычки и потенциальные проблемы в управлении финансами. Выявленные паттерны используются для формирования инсайтов и рекомендаций, повышая персонализацию отчёта.

## Основные паттерны

Ниже приведён набор паттернов, которые должен выявлять модуль. Правила могут быть доработаны или расширены в будущих версиях.

### 1. Расходы превышают доходы (`EXPENSES_EXCEED_INCOME`)

**Условия:** `totalExpense > totalIncome`. Когда общие расходы больше суммарных доходов, пользователь тратит больше, чем зарабатывает, что может привести к долгу или снижению сбережений. Сервис должен предложить рекомендации по сокращению расходов или увеличению доходов.

### 2. Высокая концентрация расходов (`HIGH_CONCENTRATION`)

**Условия:** доля крупнейшей категории ≥ 35 % (`maxCategory.percent >= 0.35`). Если одна категория занимает более трети бюджета, это указывает на слишком большую концентрацию в одной области (например, еда, жильё, развлечения). Рекомендуется обратить внимание на эту категорию и оптимизировать траты.

### 3. Сильная концентрация в топ‑3 категориях (`TOP3_DOMINANCE`)

**Условия:** суммарная доля трёх крупнейших категорий ≥ 70 % (`percentTop3 >= 0.7`). Такое распределение говорит о том, что большая часть расходов уходит в несколько сфер. Полезно разнести расходы или найти способы уменьшить суммы в этих категориях.

### 4. Крупные разовые расходы (`LARGE_SINGLE_EXPENSE`)

**Условия:** присутствует операция, сумма которой ≥ 25 % от общих расходов (`abs(amount) >= 0.25 * totalExpense`). Крупные покупки могут искажать общий бюджет и требуют дополнительного внимания. Инсайт должен указать на эту операцию и предложить проверить необходимость такой траты.

### 5. Частые мелкие траты (`FREQUENT_SMALL_EXPENSES`)

**Условия:** большое количество малых операций (например, > 10 операций, каждая менее 1 % от общего расхода). Мелкие траты могут «растворяться» в бюджете, но в сумме составляют значительную сумму. Сервис может посоветовать объединять покупки или пересмотреть микротраты.

### 6. Отсутствие доходов (`NO_INCOME`) 

**Условия:** `totalIncome = 0`, при наличии расходов. Отсутствие доходов может означать перерыв в поступлениях или только что начатый учёт. Рекомендации должны быть сфокусированы на восстановлении доходов и ограничении расходов до нормализации ситуации.

## Формат вывода

`PatternDetector` возвращает список структур вида `{ type, data }`, где:

- `type` — тип паттерна (`EXPENSES_EXCEED_INCOME`, `HIGH_CONCENTRATION`, `TOP3_DOMINANCE`, `LARGE_SINGLE_EXPENSE`, `FREQUENT_SMALL_EXPENSES`, `NO_INCOME` и т. д.);
- `data` — дополнительные данные, подтверждающие паттерн (например, название категории, процент доли, сумма операции, количество маленьких транзакций).

Формальный список типов паттернов и структура данных должны быть описаны в коде и отражены в OpenAPI‑спецификации. Паттерны служат внутренними триггерами для модулей инсайтов и рекомендаций и не обязательно отображаются напрямую пользователю.

## Пример

Пусть `totalIncome = 30 000`, `totalExpense = 45 000` и `categoryAnalytics` содержит: «Еда» 40 %, «Жильё» 20 %, «Развлечения» 15 %, прочие 25 %. Помимо этого, есть операция на 12 000. В таком случае `PatternDetector` вернёт:

```json
[
  { "type": "EXPENSES_EXCEED_INCOME", "data": { "difference": 15000 } },
  { "type": "HIGH_CONCENTRATION", "data": { "category": "Еда", "percent": 0.40 } },
  { "type": "TOP3_DOMINANCE", "data": { "percent": 0.75 } },
  { "type": "LARGE_SINGLE_EXPENSE", "data": { "amount": 12000, "percent": 0.27 } }
]
```

Эти паттерны затем будут использованы `InsightGenerator` и `RecommendationGenerator` для формирования пользовательских сообщений.
