# 11. План расширения AI‑сервиса с использованием ML

## Введение

Первая версия AI‑сервиса FinSight AI использует rule‑based подход для определения финансового состояния и генерации инсайтов и рекомендаций. В роадмапе предусмотрено развитие, предусматривающее внедрение машинного обучения для более точного анализа и персонализации. Этот документ описывает общий план такого расширения.

## 1. Сбор и подготовка данных (Dataset Builder)

Для обучения модели необходимо накопить исторические данные анализов и поведения пользователей:

- **Исходные признаки:** суммарные показатели (доходы, расходы, баланс), доли категорий, количество категорий, длительность периода, тренды по времени (например, рост расходов по категориям), паттерны (`PatternDetector`), демографические данные (если допустимо по политике конфиденциальности).
- **Целевой признак (label):** финансовое состояние, которое присваивал rule‑based `StatePredictor`, или экспертная оценка. Можно использовать обратную связь пользователя (лайк/дизлайк рекомендаций) как дополнительный сигнал.
- **Формирование датасета:** для каждого анализа формируется строка, включающая все признаки и целевую метку. Данные анонимизируются и нормализуются.

Dataset Builder должен находиться на backend‑е и периодически собирать новые данные из таблиц `FinancialAnalysis`, `CategoryAnalytics`, `Insight` и `Recommendation`. Полученный датасет хранится в безопасном хранилище.

## 2. Выбор и обучение модели

### Модель CatBoost

В роадмапе предлагается использовать **CatBoost** для предсказания финансового состояния. CatBoost хорошо работает с категориальными и числовыми признаками и требует минимальной предобработки. 

**Шаги обучения:**

1. Разделить данные на обучающую и тестовую выборки (например, 80/20).
2. Закодировать категориальные признаки (CatBoost поддерживает автоэнкодинг).
3. Настроить гиперпараметры (глубина деревьев, learning rate, количество деревьев) через кросс‑валидацию.
4. Оценить качество модели по метрикам (accuracy, F1‑score, confusion matrix). При необходимости попробовать другие алгоритмы (LightGBM, XGBoost, RandomForest).

### Предиктор `CatBoostStatePredictor`

После обучения модель интегрируется в новый модуль `CatBoostStatePredictor`, реализующий интерфейс `StatePredictor` (функция `predict_state(summary, categories) -> financialState`). Предиктор должен загружать модель из файла и выполнять предсказание на основе входных признаков. В проекте следует предусмотреть механизм выбора между rule‑based и ML‑моделью (например, через конфигурацию).

## 3. Гибридный подход

Поскольку rule‑based правила просты и прозрачны, а модель ML может давать более точные прогнозы, можно реализовать **гибридный предиктор**, который:

- использует rule‑based правила для очевидных случаев (например, `NO_DATA`, слишком высокая концентрация расходов);
- для остальных случаев вызывает `CatBoostStatePredictor`;
- объединяет результаты (например, ML‑прогноз подтверждает или корректирует состояние, предложенное rule‑based). 

В модуле `HybridOrchestrator` может настраиваться вес каждого подхода. Это позволит плавно внедрять ML, не теряя объяснимости и контролируемости.

## 4. Оценка и итерации

После внедрения ML‑модуля важно:

- сравнивать качество предсказаний rule‑based и ML‑предиктора на контрольной выборке;
- собирать обратную связь пользователей (например, рейтинги рекомендаций) и использовать её для переобучения модели;
- регулярно обновлять модель по мере накопления данных, используя MLOps‑подход (автоматизация обучения, тестирования и деплоймента моделей);
- следить за изменением распределений признаков (data drift) и при необходимости пересматривать пороги, признаки или структуру модели.

## 5. Развитие рекомендаций

В будущем рекомендации могут также генерироваться с помощью ML (например, моделей ранжирования или генеративных моделей), учитывающих индивидуальные предпочтения и поведение. Однако на первом этапе внедрение ML ограничивается предсказанием финансового состояния. Важно обеспечить совместимость с текущими rule‑based рекомендациями и предусмотреть возможность замены части генератора рекомендаций ML‑модулем.

## Заключение

Расширение AI‑сервиса машинным обучением позволяет повысить точность и персонализацию аналитики. Следуя описанному плану — сбор данных, обучение модели CatBoost, интеграция через `CatBoostStatePredictor`, гибридный подход и итеративное улучшение — разработчики могут постепенно вводить ML‑компоненты, не нарушая существующий функционал.
