# 12. Структура проекта AI‑сервиса

## Общая организация

AI‑сервис реализован как самостоятельное Python‑приложение, использующее FastAPI для создания HTTP‑интерфейса. Для обеспечения чистой архитектуры проект разделён на модули по функциональным областям: API‑контроллеры, схемы (DTO), бизнес‑логику (core), конфигурацию и тесты. Такая организация упрощает поддержку и развитие: модули слабо связаны, легко тестируются и могут заменяться без затрагивания остальной части системы.

## Рекомендуемая структура каталогов

```
ai-service/
  app/
    main.py                     # точка входа, инициализация FastAPI и маршрутов
    api/
      health_controller.py      # эндпойнт GET /health
      analysis_controller.py    # эндпойнт POST /analysis
    schemas/
      analysis_request.py       # Pydantic‑схемы для AnalysisRequest и TransactionDto
      analysis_response.py      # Pydantic‑схемы для AnalysisResponse, SummaryDto, CategoryAnalyticsDto, InsightDto, RecommendationDto
    core/
      analytics_provider.py     # реализация AnalyticsProvider
      state_predictor.py        # реализация StatePredictor
      pattern_detector.py       # реализация PatternDetector
      insight_generator.py       # реализация InsightGenerator
      recommendation_generator.py# реализация RecommendationGenerator
      analysis_orchestrator.py   # сборка всех модулей в единую операцию
    config/
      settings.py               # конфигурация сервиса (например, пороги, параметры ML‑моделей)
    tests/
      test_analytics_provider.py
      test_state_predictor.py
      test_pattern_detector.py
      test_insight_generator.py
      test_recommendation_generator.py
      test_api.py               # интеграционные тесты API
  docs/
    ...                         # документация (текущая папка)
  openapi/
    ai-service.yaml             # OpenAPI‑спецификация API
  Dockerfile                    # контейнеризация сервиса
  docker-compose.yml            # запуск зависимых сервисов (PostgreSQL, и т. д.)
  README.md                     # описание проекта, инструкции по запуску
```

## Описание ключевых файлов

- **`main.py`** — создаёт объект FastAPI, подключает роутеры, инициализирует зависимости (например, пороги для StatePredictor). Можно использовать dependency injection для передачи экземпляров модулей.
- **Контроллеры (`analysis_controller.py`, `health_controller.py`)** — определяют HTTP‑маршруты, принимают запросы, вызывают `AnalysisOrchestrator` и формируют ответы. Они не содержат бизнес‑логики.
- **Схемы (Pydantic)** — определяют формат входных и выходных данных, позволяют валидировать JSON автоматически и генерировать документацию.
- **Core‑модули** — содержат бизнес‑логику, описанную в документах `05_analytics_core.md`–`09_recommendation_generator.md`. Каждый модуль должен быть независимым и тестируемым отдельно.
- **`analysis_orchestrator.py`** — реализует последовательность вызовов модулей и сборку ответа.
- **`settings.py`** — хранит конфигурационные параметры (пороги, URL внешних сервисов, параметры ML‑моделей), считываемые из переменных окружения или конфиг‑файлов.
- **Тесты** — содержат unit‑тесты для каждого модуля и интеграционные тесты для API. Используется PyTest или аналогичный фреймворк.

## Принципы

1. **Изоляция.** Core‑модули не зависят от FastAPI и могут использоваться отдельно (например, в консольной утилите или при запуске batch‑анализа).
2. **Инъекция зависимостей.** Параметры (например, пороги для `StatePredictor`) передаются через конструкторы или конфигурацию, чтобы модуль можно было легко протестировать.
3. **Тестируемость.** Для каждого модуля должны быть предусмотрены unit‑тесты. Интеграционные тесты проверяют, что API возвращает корректные данные для типовых и граничных сценариев.
4. **Документированность.** Проект должен содержать README.md с инструкциями по запуску, а также OpenAPI‑файл, который генерируется автоматически из Pydantic‑схем или поддерживается вручную.

Подобная структура помогает соблюдать соглашения и упрощает развитие AI‑модуля в рамках единой кодовой базы FinSight AI.
