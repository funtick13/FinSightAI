# Структура API

В этом документе приведён набросок структуры API для проекта
**FinSight AI**.  Реальные определения эндпоинтов будут реализованы в
соответствующих кодовых базах серверной части и AI‑сервиса и
уточняться по мере развития проекта.  Задача данного наброска — дать
отправную точку для проектирования адресов, параметров и структур
ответов.

## API серверной части (Spring Boot)

Все эндпоинты по умолчанию начинаются с `/api`, если не указано иное.
Для передачи данных используется JSON.  Аутентификация должна
обеспечиваться JWT или сессионными куки, где это необходимо.

### Аутентификация

| Метод | Эндпоинт                  | Описание                                                                         |
|------:|---------------------------|----------------------------------------------------------------------------------|
| POST  | `/auth/register`          | Регистрация нового пользователя. Принимает email, пароль и (опционально) имя. Возвращает токен подтверждения. |
| POST  | `/auth/login`             | Аутентификация пользователя. Принимает email и пароль. Возвращает JWT.          |
| POST  | `/auth/confirm`           | Подтверждение email пользователя с помощью токена из письма.                     |
| POST  | `/auth/forgot-password`   | Инициация сброса пароля. Отправляет письмо со ссылкой для сброса.               |
| POST  | `/auth/reset-password`    | Завершение сброса пароля с использованием токена и нового пароля.               |

### Управление выписками

| Метод | Эндпоинт                   | Описание                                                                          |
|------:|----------------------------|-----------------------------------------------------------------------------------|
| POST  | `/statements/upload`       | Загрузка PDF‑выписки. Принимает multipart/form‑data с файлом, банком и месяцем. Возвращает ID выписки. |
| GET   | `/statements`              | Список всех выписок текущего пользователя. Поддерживает пагинацию.               |
| GET   | `/statements/{id}`         | Получение метаданных конкретной выписки.                                         |
| DELETE| `/statements/{id}`         | Удаление выписки и связанных операций.                                           |

### Операции

| Метод | Эндпоинт                | Описание                                                                       |
|------:|-------------------------|--------------------------------------------------------------------------------|
| GET   | `/operations`           | Получение постраничного списка операций за указанный месяц.                    |
| GET   | `/operations/{id}`      | Получение одной операции.                                                      |

### Аналитика

| Метод | Эндпоинт                | Описание                                                                 |
|------:|-------------------------|--------------------------------------------------------------------------|
| GET   | `/analytics/summary`    | Получить общие доходы, расходы и разбивку по категориям за выбранный месяц. |
| GET   | `/analytics/history`    | Список сводной аналитики за прошлые месяцы.                                 |
| GET   | `/analytics/compare`    | Сравнение двух и более месяцев.                                            |

### Рекомендации

| Метод | Эндпоинт               | Описание                                                     |
|------:|------------------------|--------------------------------------------------------------|
| GET   | `/recommendations`     | Получить рекомендации на основе правил за выбранный период. |

### Профиль

| Метод | Эндпоинт       | Описание                                         |
|------:|----------------|--------------------------------------------------|
| GET   | `/profile/me`  | Получить информацию о текущем пользователе.      |
| PUT   | `/profile/me`  | Обновить информацию о текущем пользователе.      |

## API AI‑сервиса (FastAPI)

AI‑сервис предоставляет REST‑интерфейс, который вызывается серверной частью после
успешного разбора выписки.  В рамках MVP сервис реализует правило‑ориентированный
движок; в будущем логика может быть дополнена моделями машинного обучения, но
контракт останется стабильным.

### Проверка состояния

| Метод | Эндпоинт   | Описание                                      |
|------:|------------|-----------------------------------------------|
| GET   | `/health`  | Проверка доступности сервиса. Возвращает JSON
                     | с полем `status` (`OK` при успешной работе).

### Анализ данных

| Метод | Эндпоинт      | Описание                                                        |
|------:|---------------|-----------------------------------------------------------------|
| POST  | `/analysis`   | Принимает список транзакций и возвращает агрегированные итоги,
                       | разбивку по категориям, финансовое состояние, инсайты и
                       | рекомендации.

#### Схема запроса

Входной JSON соответствует контракту `AnalysisRequest` и должен содержать
минимальный набор полей:

```json
{
  "userId": "user-uuid",
  "period": "2026-04",
  "bank": "SBERBANK",
  "statementIds": [
    "statement-uuid-1"
  ],
  "transactions": [
    {
      "id": "transaction-uuid-1",
      "date": "2026-04-16",
      "amount": 37.00,
      "category": "Транспорт",
      "description": "TPP_VPT SBERTROJKA Voronezh RUS. Операция по карте ****4188",
      "currency": "RUB"
    }
  ]
}
```

Дополнительные поля (например, `currency` для каждой операции, временные
штампы или промежуточные суммы) могут передаваться, но сервис их игнорирует.
Сервер отправляет список распарсенных транзакций за выбранный период; сервис
самостоятельно вычисляет доходы, расходы, баланс и другие показатели.

#### Схема ответа

Ответный JSON соответствует контракту `AnalysisResponse` и содержит:

```json
{
  "userId": "user-uuid",
  "period": "2026-04",
  "status": "SUCCESS",
  "summary": {
    "totalIncome": 13058.26,
    "totalExpense": 13780.40,
    "balance": -722.14
  },
  "financialState": "RISKY",
  "categoryAnalytics": [
    {
      "category": "Продукты",
      "amount": 4780.50,
      "percent": 34.7,
      "operationsCount": 10
    }
    // ... другие категории
  ],
  "topCategories": [/* первые три категории из categoryAnalytics */],
  "insights": [
    {
      "text": "Основная статья расходов — Продукты (34,7% общих расходов)"
    }
    // ... другие инсайты
  ],
  "recommendations": [
    {
      "type": "EXPENSE_OPTIMIZATION",
      "text": "Сократите расходы на категорию 'Продукты' на 5%",
      "category": "Продукты"
    }
    // ... от двух до пяти рекомендаций
  ]
}
```

Коды статуса:

- `SUCCESS` — анализ выполнен успешно, поля заполнены;
- `NO_DATA` — список транзакций пуст, агрегированные данные отсутствуют;
- `INVALID_INPUT` — входные данные некорректны (отсутствуют обязательные поля);
- `ANALYSIS_ERROR` — ошибка в процессе анализа (например, ошибка бизнес‑логики);
- `INTERNAL_ERROR` — внутренняя ошибка сервиса.

Поле `financialState` возвращает строку с обозначением состояния
(`STABLE`, `RISKY`, `EXPENSE_HEAVY`, `LOW_SAVINGS` или другое),
определённого модулем `StatePredictor`.  Конфиденс и промежуточные
значения в рамках MVP не возвращаются.
