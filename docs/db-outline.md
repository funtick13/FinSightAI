# Структура базы данных

Этот документ предоставляет обзор схемы базы данных, используемой в
системе **FinSight AI**.  Схема ориентирована на реляционную базу (например,
PostgreSQL) и может развиваться по мере работы над проектом.  Здесь
описаны только основные сущности и связи, необходимые для MVP.

## Сущности

### Пользователь (User)

Представляет зарегистрированного пользователя системы.

| Поле         | Тип        | Примечание                               |
|-------------:|-----------:|-------------------------------------------|
| `id`         | UUID       | Первичный ключ                          |
| `email`      | String     | Уникальный, индексированный             |
| `password`   | String     | Хешированный пароль                     |
| `name`       | String     | Необязательное имя пользователя         |
| `created_at` | Timestamp  | Время создания записи                   |
| `updated_at` | Timestamp  | Время последнего изменения              |

### Выписка (Statement)

Представляет PDF‑выписку, загруженную пользователем.  Содержит
метаданные о банке, отчётном месяце и расположении файла на диске.

| Поле         | Тип        | Примечание                                                      |
|-------------:|-----------:|----------------------------------------------------------------|
| `id`         | UUID       | Первичный ключ                                                 |
| `user_id`    | UUID       | Внешний ключ → User                                            |
| `bank`       | String     | Например, «Сбербанк»                                           |
| `year`       | Integer    | Год, за который выгружена выписка                              |
| `month`      | Integer    | Месяц отчётного периода (1–12)                                 |
| `file_path`  | String     | Путь к файлу в хранилище на сервере                            |
| `created_at` | Timestamp  | Время загрузки                                                 |

### Операция (Operation)

Представляет отдельную транзакцию, извлечённую из выписки.  Каждая
операция связана с одной выпиской и одним пользователем.

| Поле            | Тип        | Примечание                                                         |
|---------------:|-----------:|---------------------------------------------------------------------|
| `id`           | UUID       | Первичный ключ                                                    |
| `statement_id` | UUID       | Внешний ключ → Statement                                         |
| `user_id`      | UUID       | Внешний ключ → User                                              |
| `date`         | Date       | Дата транзакции                                                  |
| `amount`       | Numeric    | Положительные значения — доходы, отрицательные — расходы         |
| `description`  | String     | Описание из выписки                                             |
| `category`     | String     | Категория из выписки                                             |

### Финансовый анализ (FinancialAnalysis)

Хранит результаты анализа операций пользователя за конкретный месяц.
Каждая запись представляет один запуск AI‑сервиса и содержит
агрегированные показатели, финансовое состояние и связи с
категорией расходов, инсайтами и рекомендациями.

| Поле               | Тип        | Примечание                                                  |
|-------------------:|-----------:|--------------------------------------------------------------|
| `id`               | UUID       | Первичный ключ                                              |
| `user_id`          | UUID       | Внешний ключ → User                                         |
| `year`             | Integer    | Год отчётного периода                                       |
| `month`            | Integer    | Месяц отчётного периода                                     |
| `total_income`     | Numeric    | Сумма всех доходов                                           |
| `total_expense`    | Numeric    | Сумма всех расходов (положительное число)                    |
| `balance`          | Numeric    | Разница `total_income – total_expense`                      |
| `financial_state`  | String     | Результат модуля StatePredictor (`STABLE`, `RISKY`, и т.д.) |
| `created_at`       | Timestamp  | Время формирования записи                                   |

### Аналитика по категориям (CategoryAnalytics)

Хранит суммы и доли расходов по каждой категории в рамках конкретного
финансового анализа.

| Поле            | Тип    | Примечание                                       |
|----------------:|-------:|-------------------------------------------------|
| `id`            | UUID   | Первичный ключ                                  |
| `analysis_id`   | UUID   | Внешний ключ → FinancialAnalysis                |
| `category`      | String | Название категории                              |
| `amount`        | Numeric| Сумма расходов по категории                     |
| `percent`       | Numeric| Доля от общего расхода (0–100)                  |
| `operations_count` | Integer| Количество операций в категории               |

### Инсайт (Insight)

Текстовое сообщение, объясняющее пользователю структуру расходов.
Каждый инсайт связан с конкретным результатом анализа.

| Поле         | Тип    | Примечание                                   |
|-------------:|-------:|---------------------------------------------|
| `id`         | UUID   | Первичный ключ                               |
| `analysis_id`| UUID   | Внешний ключ → FinancialAnalysis            |
| `text`       | Text   | Текст инсайта                               |

### Рекомендация (Recommendation)

Представляет совет, сформированный AI‑сервисом для пользователя в рамках
конкретного анализа.  Рекомендации хранятся, чтобы их можно было
быстро отдавать на мобильное приложение.

| Поле         | Тип    | Примечание                                           |
|-------------:|-------:|-----------------------------------------------------|
| `id`         | UUID   | Первичный ключ                                     |
| `analysis_id`| UUID   | Внешний ключ → FinancialAnalysis                  |
| `type`       | String | Тип рекомендации (например, `EXPENSE_OPTIMIZATION`) |
| `text`       | Text   | Текст рекомендации                                 |
| `category`   | String | Связанная категория (опционально)                  |
| `created_at` | Timestamp | Время генерации рекомендации                     |

## Связи

* Один **User** может иметь много **Statements**.
* Один **Statement** принадлежит одному **User** и содержит много **Operations**.
* Одна **Operation** принадлежит одному **Statement** и одному **User**.
* Один **User** может иметь несколько записей **FinancialAnalysis** (например,
  при повторном запуске анализа или обновлении логики).
* Одна запись **FinancialAnalysis** связана с одним **User** и может иметь
  множество **CategoryAnalytics**, **Insights** и **Recommendations**.
* Каждая **CategoryAnalytics**, **Insight** и **Recommendation** принадлежит
  конкретной записи **FinancialAnalysis**.

## Развитие схемы

* **Категории** — вынести категории в отдельную таблицу с
  дополнительными метаданными (иконки, перевод и т.п.).
* **Работа с валютой** — поддерживать операции в нескольких валютах.
* **Метки и бюджеты** — добавить пользовательские метки и учет бюджета.
* **Журнал изменений** — отслеживать изменения выписок и операций для
  прозрачности.
* **Настройки пользователя** — хранить настройки уведомлений и отображения.

---

Этот обзор предназначен для старта.  При реализации схему нужно
уточнять, обеспечивать ссылочную целостность, корректное индексацию
и соблюдать лучшие практики (например, хранить пароли в виде хеша).
Финальная схема базы должна документироваться через миграции или ER‑диаграмму.
